# Vercel Deployment Configuration for Laravel 12

I have completed the necessary changes to host your Laravel 12 project on Vercel, specifically configured to use **Supabase (PostgreSQL)** as your external database.

## Changes Made

### 1. Serverless Bridge
- Created [api/index.php](file:///e:/Git_WIP/3.%20University%20repositories/uits-research-archive.Kryton/api/index.php) which acts as the entry point for Vercel's PHP runtime. It routes all incoming requests to Laravel's standard `public/index.php`.

### 2. Ephemeral Filesystem Handling
- Created [app/Providers/VercelServiceProvider.php](file:///e:/Git_WIP/3.%20University%20repositories/uits-research-archive.Kryton/app/Providers/VercelServiceProvider.php). This provider automatically:
  - Detects if the app is running on Vercel.
  - Redirects compiled Blade views to the writable `/tmp/views` directory.
  - Ensures the directory exists at runtime to prevent crashes.

### 3. Service Provider Registration
- Updated [bootstrap/providers.php](file:///e:/Git_WIP/3.%20University%20repositories/uits-research-archive.Kryton/bootstrap/providers.php) to register the new `VercelServiceProvider`.

### 4. Build & Routing Configuration
- Verified [vercel.json](file:///e:/Git_WIP/3.%20University%20repositories/uits-research-archive.Kryton/vercel.json). It is configured to:
  - Run `npm run build` (Vite) and output static assets.
  - Use `vercel-php@0.6.0` for the Laravel runtime.
  - Route all static build assets from `/build/*`.

## Database Setup (Supabase)

> [!IMPORTANT]
> To connect to Supabase, you **must** add the following environment variables in your Vercel Project Settings:
> - `DB_CONNECTION`: `pgsql`
> - `DB_HOST`: *Your Supabase DB Host* (found in Supabase Settings > Database)
> - `DB_PORT`: `5432`
> - `DB_DATABASE`: `postgres`
> - `DB_USERNAME`: `postgres`
> - `DB_PASSWORD`: *Your Supabase DB Password*
> - `DB_SSLMODE`: `require`
