# Modernizing Vercel Configuration

Vercel has issued a warning because our `vercel.json` uses the legacy `builds` property. To future-proof the deployment and resolve this warning, we will transition to the modern `functions` configuration.

## User Review Required

> [!NOTE]
> **Zero Config Transition**: This change moves the project towards Vercel's "Zero Config" approach for static assets while explicitly defining the PHP serverless function.
> **Deployment Settings**: Once these changes are pushed, you should verify if you need to manually set the **Framework Preset** to "Other" and **Output Directory** to `public` in the Vercel Dashboard (though the configuration file usually handles this).

## Proposed Changes

### 1. Update Vercel Configuration
Transition from the legacy `builds` array to the modern `functions` and `routes`/`rewrites` structure.

#### [MODIFY] [vercel.json](file:///e:/Git_WIP/3.%20University%20repositories/uits-research-archive.Kryton/vercel.json)
- Remove the `builds` key.
- Add `functions` key pointing `api/index.php` to `vercel-php@0.7.1`.
- Clean up `env` variables (some are better handled in the Vercel Dashboard).
- Adjust `routes` to ensure Vite assets are served correctly.

### 2. Optimize Vercel Build
Add a `.vercelignore` file to ensure the build environment is clean and installs dependencies from scratch.

#### [NEW] [.vercelignore](file:///e:/Git_WIP/3.%20University%20repositories/uits-research-archive.Kryton/.vercelignore)
- Ignore `vendor`, `node_modules`, and local documentation.
